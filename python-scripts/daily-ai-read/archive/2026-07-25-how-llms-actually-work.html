What Claude Is Actually Doing When You Type a Prompt

Every time you send a message to Claude Code, you're not talking to something that "knows" things the way you do. You're firing up an extraordinarily powerful autocomplete engine — one trained on a chunk of the entire written internet — and the output can feel eerily intelligent. Here's what is actually happening under the hood.

The 2-minute version

  • Tokens, not words. AI models don't read words — they read chunks called tokens, roughly ¾ of a word each. Everything is measured, priced, and limited in tokens.
  • One job, done at massive scale. An LLM is trained on one objective: predict the next token given all the tokens before it. That's the whole trick.
  • Generation is a loop. When the model replies, it picks one token, adds it to the sequence, then picks the next one — thousands of times — until it decides to stop.
  • Context window = working memory. The model can only "see" a limited number of tokens at once. Overflow that limit and it starts forgetting the beginning of your conversation.
  • RLHF turns autocomplete into an assistant. A second training stage uses human feedback to steer the raw model away from garbage output and toward helpful, honest replies.

Step 1: Everything gets chopped into tokens

Before an AI model can read a single word you've written, it has to convert your text into a format it can process mathematically. The unit it uses is called a token.

A token is not exactly a word. It's a chunk of text — sometimes a full word, sometimes just part of one, sometimes punctuation. In English, one token corresponds to roughly three-quarters of a word, or about four characters of text. So the sentence "I edit videos in Premiere" might become five or six tokens: "I", "edit", "vid", "eos", "in", "Premiere". The model never sees letters — only these numbered chunks.

Why does this matter to you? Because tokens are the unit of cost and capacity for every AI model you use. When an API bill says "$2 per million input tokens," that's how many chunks of text you fed in. When a model says it has a "200,000 token context window," that's how much text it can hold in memory at once — more on that in a moment.

Step 2: Training — reading the world, one prediction at a time

Here is the part that surprises most people: every large language model (LLM — that's the technical name for a model like Claude, GPT, or Gemini) was trained on one single objective. The goal was: given all the tokens you've seen so far, predict the next token.

Think of it like a cloze test you might have taken in school — a sentence with the last word blanked out. The model's job was to fill in that blank. Now imagine doing that for hundreds of billions of sentences scraped from books, websites, code repositories, academic papers, and more. The model saw so much text, and made so many predictions, that it had to develop an internal representation of how language works, how ideas connect, how code is structured, and what facts tend to be true — not because anyone programmed those things in, but because they were the only way to get the prediction right.

This phase is called pretraining. The model underneath Claude or ChatGPT began as a raw pretraining result: extremely knowledgeable about how language works, but with no idea how to be a helpful assistant. It would just as happily continue a racist rant as write a Python script, because both patterns existed in the training data.

The underlying system that makes next-token prediction work efficiently at scale is called a Transformer — a specific neural network architecture first published in a 2017 research paper. A neural network is a layered mathematical system loosely inspired by how neurons connect in a brain. What made the Transformer special was a trick called self-attention, which lets the model weigh how relevant every earlier token is to the one it's currently predicting. When the model is deciding what word follows "she picked up her," self-attention lets it look back and figure out who "she" refers to, even if that was 200 tokens ago.

Step 3: Generating a response — one token at a time

When you hit "send" on a prompt, the model doesn't draft the entire reply at once. Instead, it runs the same prediction loop over and over:

  1. It looks at your prompt (all its tokens).
  2. It produces a probability distribution — a ranked list of every possible next token and how likely each one is.
  3. It samples from that list and picks one token.
  4. That token gets appended to the sequence.
  5. Repeat from step 1, now with one more token in the input.

This is why AI responses stream onto your screen word-by-word rather than appearing all at once — you're literally watching the loop run in real time.

The temperature setting you may have seen in API settings controls how adventurous that sampling step is. Low temperature = pick almost always the most likely token (predictable, consistent output). High temperature = pick from further down the probability list more often (more creative, occasionally more weird).

This also explains why models hallucinate — a term for when they confidently state something false. The model is not lying. It doesn't have beliefs. It's producing whatever token is statistically likely to follow, and sometimes a confident-sounding false claim is more statistically probable than "I don't know."

Step 4: The context window — the model's working memory

At every step of the generation loop, the model looks back at all previous tokens — but only up to a limit. That limit is called the context window. Think of it as the model's desk: it can only have so many papers spread out in front of it at once. Once you pile on more papers than the desk fits, the oldest ones fall off the back edge and the model can no longer reference them.

The context window holds everything: your system prompt, the conversation history, documents you paste in, and the model's own replies so far. Claude Sonnet 5, which launched June 30, 2026, has a 1,000,000-token context window — that's roughly 750,000 words, or about the length of eight average novels. A few years ago, most models topped out at 4,000 tokens.

But bigger context windows cost more to run. Every token in that window has to be processed during self-attention, and the compute grows fast as the window fills up. That's why API pricing is per token, not per message.

Step 5: RLHF — turning autocomplete into an assistant

After pretraining, the raw model still doesn't behave like a good assistant. A second training stage called RLHF (Reinforcement Learning from Human Feedback) fixes that. Here's the simplified version of how it works:

  1. Supervised fine-tuning (SFT): Human writers demonstrate ideal conversations — here's a good prompt, here's a good answer. The model trains on these examples directly.
  2. Reward modeling: Human raters compare pairs of model outputs and rank which one is better. Their preferences train a separate "reward model" — essentially a judge that scores responses.
  3. Reinforcement learning: The main model is tuned to generate responses that score higher with the judge, without wandering too far from what it already knows.

RLHF is why Claude says "I'm not sure" instead of hallucinating more confidently, why it declines certain requests, and why it follows instructions in a natural conversation format rather than just continuing a text document. The raw pretraining data doesn't teach any of that — RLHF does.

Why this matters for your work

Understanding this loop makes you a meaningfully better AI user right now:

  • Longer context = more expensive. When you build an automation in Claude Code that dumps a 10,000-word document into every prompt, you're paying for every token of that document on every call. Trimming inputs isn't just good practice — it directly cuts your API bill.
  • Prompts are part of the input, not separate from it. Your instruction, the conversation history, and any examples you give are all tokens the model sees as one continuous stream. A 500-word system prompt costs real tokens every single request.
  • Hallucinations aren't bugs you can patch. They're a structural feature of next-token prediction. The fix is verification — build your automations to double-check factual outputs rather than trusting them blindly.
  • Temperature is a creative dial you can turn. If you're building a tool that writes social captions, a slightly higher temperature gives more varied output. For a tool that parses invoice data, you want temperature near zero so results are consistent and predictable.

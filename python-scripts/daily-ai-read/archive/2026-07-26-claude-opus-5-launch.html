```html Claude Just Got a New Model — and It Affects How You Build

Daily AI Read — Issue #2 — July 26, 2026

Two days ago, Anthropic quietly shipped a new AI model called Claude Opus 5 — and if you use Claude Code to build anything, this one is directly about your tools changing under your feet. Here is exactly what changed, what it means, and one thing you can do about it today.

The 2-minute version

  • Anthropic released Claude Opus 5 on July 24, 2026 — a new model that performs nearly as well as its most powerful widely available model (Fable 5) at half the price.
  • It is now the default model in Claude Max and the strongest model in Claude Pro — so if you opened Claude Code this weekend, you may already be using it.
  • The biggest new feature is an effort setting — a dial (low / medium / high / xhigh / max) that lets you control how hard the model works on any task, trading speed and cost against depth and accuracy.
  • On the industry's most important coding benchmark, Opus 5 more than doubled its predecessor's score and beat the flagship Fable 5 model outright.
  • Pricing is unchanged from the previous Opus model: $5 per million input tokens, $25 per million output tokens on the API.

First: the Claude family tree, explained simply

Anthropic makes several different versions of Claude at once, each trading off intelligence, speed, and cost. Think of it like car trim levels. As of this week, the lineup from most to least powerful looks roughly like this:

Model Analogy API Cost (input / output)
Fable 5 Formula 1 car $10 / $50 per M tokens
Opus 5 ← new High-performance sedan $5 / $25 per M tokens
Sonnet 5 Everyday reliable car $3 / $15 per M tokens
Haiku 4.5 Fuel-efficient compact $1 / $5 per M tokens

A quick vocab note: tokens are the chunks that AI models read and write (roughly 3/4 of a word each). When you see prices like "$5 per million input tokens," that is how API users (developers calling Claude directly from code) get charged. If you are on a flat-rate Claude Pro or Max subscription, you do not pay per token — but the model still burns tokens, and that affects how fast you hit your usage limits.

Before Opus 5 arrived, the gap between Sonnet 5 and Fable 5 was wide. Opus 5 now slots in between them, offering near-flagship intelligence without the flagship price tag.

What actually changed with Opus 5

1. It can beat the flagship on coding tasks. Anthropic uses a test suite called Frontier-Bench v0.1 to measure how well a model handles real software engineering work: multi-file changes, debugging, and building features from a spec. That is the benchmark that matters most if you are using Claude Code. Opus 5 scored 43.3% on this test — more than double the previous Opus model (18.7%) and ahead of Fable 5 (33.7%). On a second test measuring novel problem-solving (ARC-AGI-3), Opus 5 scored 30.2% — roughly four times higher than OpenAI's comparable model, GPT-5.6 Sol.

2. It checks its own work. Anthropic says Opus 5 can check and improve its own work through iteration, and build its own tools through code when it needs them. This is a meaningful step for agentic work — a term worth defining. An agentic AI is one that does not just answer a single question and stop. It takes a goal, breaks it into steps, executes those steps one after another (including running code, reading files, and calling other tools), checks the results, and adjusts — all without you having to babysit each move. Claude Code's whole value proposition is agentic work, so improvements here matter directly.

3. Pricing is flat. Anthropic kept API pricing equal to the previous Opus 4.8 version. Given the performance jump, this is a genuine improvement in value, not just a new model at a higher price.

The effort setting: the most practical new feature

This is the part that has the biggest day-to-day impact. Opus 5 introduces a low/medium/high effort toggle — and in practice there are five levels: low, medium, high, xhigh, and max. The default is high.

Here is what these settings actually change — and this is important: it is not just "thinking time." Effort controls how many files the model reads, how much it verifies, and how far it pushes through a multi-step task before checking in with you.

Think of it like hiring a contractor. On low effort, they show up, do the obvious work, and hand it back fast. On max effort, they read every blueprint, double-check every measurement, and only stop when they are sure the work is right — but they also bill more hours. Effort changes the number of tokens the model uses, not the per-token price. Lower effort settings can cut token usage meaningfully at similar accuracy, so real cost per task varies even at a fixed price per million tokens.

Anthropic recommends starting with high (the default) and adjusting based on your results: step up to xhigh for demanding coding and agentic work, or to max when a task justifies unconstrained token spending, and use low and medium liberally as your primary control for token cost and response time wherever quality holds.

One important caveat from the docs: switching effort levels mid-conversation invalidates the prompt cache. A prompt cache is a saved copy of your conversation context that the model can reuse instead of reprocessing from scratch every time, which saves tokens and money. Changing effort or speed mid-conversation invalidates the prompt cache, which can cost more than the effort saving returns. Set it per workload, not per request.

How you actually access it

Opus 5 serves as the default model on Claude Max and the top option on Claude Pro. So if you opened Claude Code this weekend, you may already be running it. In Claude Code, Anthropic defaults to high effort in both the API and the terminal tool.

In Claude Code's terminal interface, you can switch models by typing /model and selecting from the list. You can also set effort by adjusting your configuration file or passing the effort parameter directly in your prompts when writing scripts that call the API.

Why this matters for you

You use Claude Code to build automation tools. Every session you have with it is exactly the kind of agentic, multi-step coding work that Opus 5 was built and benchmarked for. The jump in coding scores is not abstract — it means the model you are already using should now handle more complex tasks with fewer wrong turns.

The effort setting is your new budget lever. When you are in the early, exploratory part of a project — sketching out structure, asking "what should this automation even do?" — medium effort will move faster and cost fewer tokens. When you are in the hard part, debugging something broken across multiple files, xhigh effort is probably worth the extra tokens.

For your content and marketing work — drafting captions, writing scripts, brainstorming campaign angles — there is no reason to burn Opus 5 tokens on a short, structured task. Sonnet 5 (available on all plans) handles that tier of work fine. Knowing which model to reach for, and at what effort level, is now a skill that saves real time and money.

Try this today (5 minutes)

Open Claude Code and type /model to confirm you are on Opus 5. Then give it a real coding task from a current project — something you have been putting off because it felt complex. At the start of your prompt, add the phrase: "Work at high effort, verify your own output before finishing." Watch what the model does differently. You are teaching yourself what this model is capable of at its default setting, which makes every future session more intentional.

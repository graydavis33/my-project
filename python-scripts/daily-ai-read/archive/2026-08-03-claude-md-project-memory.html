The File That Teaches Claude About Your Project

Every Claude Code session starts with a blank slate. One small file called CLAUDE.md changes that permanently. Here is exactly what it is, where it lives, and what to put in it.

THE 2-MINUTE VERSION

  • Claude Code forgets everything when you close a session. CLAUDE.md is the fix.
  • It is a plain text file in your project folder that Claude reads automatically at the start of every session — before you type a single thing.
  • You write it once. It loads every time, forever, with no extra effort.
  • Run /init inside Claude Code and it writes a first draft for you.
  • Keep it under 200 lines — every line costs space Claude needs for your actual code.

Why Claude Keeps Forgetting You

Every Claude Code session starts with a fresh context window. Context window just means the working memory Claude has right now — everything it can "see" during a single conversation. When you close the session, that memory is gone completely.

That means Claude wakes up tomorrow with no idea that your footage organizer uses a specific folder structure, that your Payday app is written in Python, or that you always want short functions with comments. You have to re-explain all of it, every time you start a new session.

This is not a bug. It is how large language models — the AI technology powering Claude — work by design. But Claude Code's official memory system has a built-in fix.

What CLAUDE.md Is

CLAUDE.md is a plain text file — written in Markdown, the simple formatting language that uses # for headings and - for bullet points — that you place in the root folder of your project. Root folder just means the main folder, not a subfolder inside it.

Claude Code finds it automatically and reads it before anything you type. Think of it like a sticky note taped to the front of a filing cabinet. Every time a new employee (Claude) opens that cabinet, they read the note first. They instantly know your preferences without being told.

The official Claude Code overview puts it plainly: CLAUDE.md is where you store "project-specific instructions, conventions, and context that Claude should know every session."

Two Memory Systems: One You Write, One Claude Writes

Claude Code actually has two ways of carrying knowledge across sessions:

1. CLAUDE.md files — instructions you write yourself. You control what goes in, and it loads every session automatically.

2. Auto memory — notes Claude writes for itself as you work together. If you correct Claude mid-session ("do not use that function, use this one instead"), it can save that correction automatically and remember it next time. These notes live in a separate hidden folder on your computer, not inside CLAUDE.md.

Both are loaded at the start of every conversation. One important distinction the official docs make: Claude treats both systems as instructions to follow, not locked-in rules it enforces. Think of it like a style guide a developer reads on their first day — not a padlocked setting. If you need to truly block an action, Claude Code uses a different feature called hooks. But for everything you need day to day, CLAUDE.md is the right tool.

What to Actually Put In It

The official Anthropic blog on CLAUDE.md says to include: build commands, code style preferences, architecture decisions, testing instructions, and project-specific warnings. No required format exists. Keep it short and human-readable.

Here is a concrete example of what a CLAUDE.md for your footage organizer might look like:

# Footage Organizer — Project Context ## What This Does Indexes video files from an external SSD and organizes them by date and client. ## Tech Stack Python 3. Uses os and pathlib only. No frameworks. ## Style Rules - Short functions, one job each - Add a one-line comment above every function - Print progress to the terminal so I can watch it run ## Do Not - Do not rename files without asking me first - Do not touch anything outside the /footage folder

That is it. Twenty lines that save five minutes of re-explaining every session. The rule, backed by the official docs: be specific and concrete. "Use 2-space indentation" works. "Format code nicely" does not — Claude cannot verify what "nice" means, so it guesses.

How to Create One in Under a Minute

You do not have to write CLAUDE.md from scratch. Claude Code has a slash command — a shortcut that starts with / — called /init. Type it inside Claude Code while you are in your project folder. Claude analyzes your codebase and writes a first draft of CLAUDE.md for you — including build commands and conventions it finds on its own.

After it generates the file, read every line and remove anything inaccurate or unnecessary. The official docs warn: files over 200 lines consume more of the context window and Claude follows them less reliably. Every line costs space. Trim it the way you trim a caption — cut everything that does not need to be there.

One more detail worth knowing: CLAUDE.md has a live file watcher. If you edit the file while a session is already open, Claude picks up the changes immediately. You do not need to restart.

Where CLAUDE.md Lives and How It Connects to Your Repo

Your CLAUDE.md file sits in your project's root folder — the same place as the rest of your project files in graydavis33/my-project. Because it is a regular file in the repo, it gets committed and pushed to GitHub along with your code. That is a feature, not an accident: the instructions travel with the project. This is why the last four issues — commits, push, pull — matter. You now have the mechanics to actually ship a CLAUDE.md.

There is also a companion file called CLAUDE.local.md. This one holds personal preferences you do not want to share — like a note about your SSD's mount path or a local test command. You add CLAUDE.local.md to your .gitignore file (.gitignore is a list that tells git which files to skip when committing) so it stays on your machine only and never goes to GitHub.

If you have preferences that should apply across every project — not just one — you can create a global CLAUDE.md at ~/.claude/CLAUDE.md. The tilde (~) is Mac shorthand for your home directory. That file loads in every session, across every project, on your machine.

Why This Matters for You

You have at least six tools living in graydavis33/my-project: the Payday budgeting app, the footage organizer, caption scripts, the invoice tracker, the email agent, and this Daily AI Read email. Right now, every time you open Claude Code to work on one of them, Claude starts from zero. It does not know what the tool does, what language it is in, or what your rules are.

A CLAUDE.md for each tool — even ten to fifteen lines each — means Claude walks in on day two already briefed on the project. That is the difference between a contractor who read the brief and one who showed up cold and spent the first hour asking basic questions. The time you spend writing these files once pays back every single session going forward.

TRY THIS TODAY

Open Claude Code inside your project folder and type this at the prompt:

/init

Claude will scan your project and generate a draft CLAUDE.md. Read it line by line — remove anything wrong, vague, or unnecessary. Then commit the file. It is now part of your repo and will load automatically in every future Claude Code session. Five minutes of setup that pays back every day.

TEST YOURSELF

1. What happens to Claude's memory when you close a Claude Code session?

Answer: It is completely wiped. Each session starts with a fresh context window. This is how large language models work by design — they do not retain anything between separate conversations unless a persistence system like CLAUDE.md explicitly reloads it.

2. In plain terms, what is a context window?

Answer: The working memory Claude has available during a single session — everything it can "see" at once, including your prompts, its responses, and any files it has read. When the session closes, that window is cleared.

3. What is CLAUDE.md, and where does it sit in your project?

Answer: CLAUDE.md is a plain Markdown text file in the root (main) folder of your project. Claude Code reads it automatically at the start of every session, before you type anything. It holds your persistent instructions for that project.

4. What slash command generates a first draft of CLAUDE.md from your existing codebase?

Answer: /init. You type it inside Claude Code while in your project folder. Claude analyzes the codebase and writes a starting file. You still need to review and trim what it produces.

5. Name the two memory systems Claude Code uses across sessions and describe the key difference between them.

Answer: (1) CLAUDE.md — instructions you write and control. (2) Auto memory — notes Claude writes for itself based on corrections you make during sessions. You write one intentionally; the other builds up automatically. Both load at the start of every conversation.

6. Why should you keep CLAUDE.md under 200 lines?

Answer: Every line the file takes up is space inside the context window that could be used for your actual code and conversation. The official docs note that files over 200 lines consume more context and Claude follows them less reliably — longer is not better here.

7. What is the difference between CLAUDE.md and CLAUDE.local.md?

Answer: CLAUDE.md gets committed to your repo and pushed to GitHub — it travels with the project and is shared. CLAUDE.local.md holds personal preferences that stay on your machine only. You add it to .gitignore so git skips it and it never leaves your computer.

8. You are mid-session in Claude Code and realize you forgot to add an important rule to CLAUDE.md. Do you need to restart the session?

Answer: No. CLAUDE.md has a live file watcher. If you edit and save the file while a session is already open, Claude Code detects the change and picks up the new content immediately — no restart needed.

9. You want one instruction — "always respond in plain English, no jargon" — to apply in every Claude Code project you ever open, not just one. Where do you put it?

Answer: In a global CLAUDE.md at ~/.claude/CLAUDE.md on your Mac. The ~ is shorthand for your home directory. This file loads for every Claude Code session on your machine, regardless of which project you are in.

10. Which of these is a better CLAUDE.md instruction — and why? (A) "Write clean, readable code." (B) "Add a one-line comment above every function explaining what it does."

Answer: (B). It is specific and verifiable — Claude can look at its own output and check whether every function has a one-line comment above it. Option (A) is abstract; "clean" and "readable" mean different things to different people, so Claude ends up guessing. The official docs say instructions should be "concrete enough to verify."

What Is a "Repo"? The Folder That Never Forgets

You already own one. It holds every tool you have ever built. Today you will finally know exactly what that means — and why it has been quietly saving you this whole time.

THE 2-MINUTE VERSION

  • A repository (repo) is a folder that also stores its complete history — every change, forever.
  • That history is managed by a tool called Git. GitHub is just a website that stores Git repos online.
  • You have two copies: a local one on your Mac, and a remote one on GitHub. They stay in sync via push and pull.
  • Your repo is graydavis33/my-project — it already holds every tool you have built with Claude Code.
  • The auto-commit at the end of every Claude Code session is Git saving a dated snapshot into your repo automatically.

The Plain-English Answer

A repository — "repo" for short — is a project folder with one superpower: it remembers every version of every file inside it, forever.

A normal folder only holds what is in it right now. Delete a line of code, save the file, and that line is gone. A repo is different. Every time you save a snapshot (called a commit), Git records what changed and when. You can scroll back to any moment in your project's life and see exactly what your code looked like.

Git is the free software that does this tracking. It runs invisibly on your computer, inside your project folder. You do not need to understand all of Git right now. Just know it is the engine underneath every repo.

The Analogy That Actually Sticks

Think of a repo like a Google Doc — but for code, and far more powerful.

Google Docs has "Version History." You can click back and see how the document looked last Tuesday. A repo does the same thing, except you choose exactly when to save a version, and you attach a short message to each snapshot describing what you changed.

Real-world equivalent: imagine a contractor who photographs every room of a house at the end of each workday. The homeowner can always say "show me what it looked like Wednesday." Each photo is a commit. The full photo album is the repo.

Two Copies: Local and Remote

This is where GitHub enters. GitHub is a website — owned by Microsoft — that hosts repos online. Think of it as a Google Drive built specifically for Git repos.

When you work with a repo, you typically have two copies at once:

  • Local repo — the copy on your Mac (or PC). This is where you actually write and edit code.
  • Remote repo — the copy on GitHub's servers. This is your off-device backup, and how your Mac and PC share the same codebase.

Sending changes from local up to remote is called a push. Grabbing changes from remote back down to local is called a pull. You will hear these two words constantly. They are just directions — outgoing vs. incoming.

What Is Actually Inside a Repo Folder

If you open your project folder on your Mac, you will see your code files — JavaScript, Python, HTML, whatever the tools are made of. But there is also a hidden folder called .git. That is where Git stores the entire history database. Do not touch it. Do not delete it. It is the repo's memory.

You will also likely see a file called README.md. That is a plain-text description of the project — it displays as the front page of your repo on GitHub. Think of it as the label on the outside of the filing cabinet.

Why This Matters For You

Say Claude Code helps you upgrade your footage organizer — new feature, indexes faster. You test it, love it, and then realize three days later it broke the search function. Without a repo, you are stuck with the broken version. With a repo and auto-commits, you open GitHub, scroll back to three days ago, and restore exactly what was working. This takes minutes, not hours.

This is also why your tools work on both your Mac and Windows PC without a USB drive or email chain. Your Mac pushes to GitHub. Your PC pulls from GitHub. The remote repo is the shared bridge between two machines that never talk directly to each other.

And because your repo is public on GitHub, it also functions as a portfolio — any developer you ever hire or collaborate with can read the code instantly, no file transfers needed.

Test Yourself

1. In one sentence, what is a repository?

Answer: A repository is a project folder that stores the complete history of every change ever made to the files inside it. This matters because it lets you recover any previous version of your work — something a normal folder cannot do.

2. What is Git, and how is it different from GitHub?

Answer: Git is free software that runs on your computer and tracks the history of your code. GitHub is a website that stores those Git repos online so they are backed up and accessible from anywhere. Git is the engine; GitHub is the parking garage.

3. What is a "local" repo versus a "remote" repo?

Answer: A local repo is the copy on your own machine — where you do your actual work. A remote repo is the copy hosted online on GitHub. They are the same project in two places, kept in sync by push and pull.

4. What does "push" mean?

Answer: Push means sending your latest changes from your local repo up to the remote repo on GitHub. Think of it as uploading — you are pushing your work outward, off your machine and onto the internet.

5. What does "pull" mean?

Answer: Pull means downloading the latest changes from the remote repo on GitHub down to your local machine. If you built something on your Mac, you would pull on your Windows PC before working there so it has the newest version.

6. What is the hidden ".git" folder, and what happens if you delete it?

Answer: The .git folder is where Git stores your entire project history. Deleting it would wipe out every snapshot ever made and turn your repo back into a plain, memoryless folder — you would lose all ability to roll back changes.

7. Your caption script breaks after a Claude Code session. What does having a repo let you do that a plain folder would not?

Answer: You can open your commit history on GitHub, find the last working version, and restore the script. With a plain folder, the broken version is all you have — there is no history to roll back to.

8. Why does your code work on both your Mac and Windows PC without any manual file transfers?

Answer: Your Mac pushes changes to the GitHub repo, and your PC pulls them down. The remote repo acts as the shared middle point. Without it, you would have to copy files by hand every time you switched machines.

9. At the end of every Claude Code session, your setup auto-commits and auto-pushes. In plain English, what is happening in that moment?

Answer: Git saves a labeled snapshot of every file that changed during the session — that is the commit. Then it sends that snapshot up to your repo on GitHub — that is the push. It is an automatic save-and-backup that runs without you thinking about it.

10. What does a "diff" show you, and where do you find one?

Answer: A diff shows exactly what changed between two versions of a file — lines added appear in green, lines removed appear in red. You find one by clicking any commit in your commit history on GitHub. It is the fastest way to understand what a session actually changed.
